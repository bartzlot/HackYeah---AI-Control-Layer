Scope: web and desktop AI apps. Onboarding/identity and catalog/uploads are in sibling files; here only the transport and prompt shape. Conclusions:
- Commercial inline products (Zscaler, Netskope, Palo Alto, Cloudflare) all do what we plan: decrypt, parse the app's JSON body per app (custom connector from captured traffic), match DLP, block. None parses generically; all give up on pinned desktop apps and WebSocket is the weak spot (Zscaler's own advice is to drop WS).
- Endpoint agent or browser extension = different place in the stack (before TLS, sees paste/typing and non-network leaks); out of scope, mention as limitation.
- ECH: with an explicit proxy the client sends `CONNECT host:443` in clear, so ECH never hides the host `[INFERENCE]`; it only matters for transparent / local capture modes. Chrome via explicit proxy never used HTTP/3 in the spike (all 796 responses h2 or h1.1). Desktop apps (Chromium-based) may use QUIC in local capture mode: block UDP/443 at the host firewall to force TCP `[INFERENCE, standard practice; Cloudflare docs show the UDP proxy requirement]`.
- Body rewrite safety `[INFERENCE]`: ChatGPT sentinel/PoW tokens and Gemini `at` are not derived from the body (wrapper code builds them without the prompt), so in-place redaction should not invalidate them. Must be proven with a live fixture.

## Further

**Recommendation for our build**

1. **Adapter scope (14 h budget):** build the generic adapter first (D1), then precise adapters in this order, stopping when time is out: ChatGPT web (JSON in, SSE out), Claude web (JSON in, SSE out), then Copilot consumer (WS) and Perplexity (flat JSON) only if the first two are green. Gemini: generic + a small `f.req` double-decoder for extraction only. Mistral, Grok, Meta, DeepSeek: generic only. Desktop apps: tunnel plus domain app-control, no decryption, until a live test says otherwise.
2. **Decrypt allowlist** (everything else tunnelled): `chatgpt.com`, `*.chatgpt.com` (incl. `ws.chatgpt.com`), `files.oaiusercontent.com` (headers only, body to the catalog sibling), `claude.ai`, `gemini.google.com`, `copilot.microsoft.com`, `www.perplexity.ai`, `chat.mistral.ai`, `grok.com`, `www.meta.ai`, `chat.deepseek.com`. Never `*.cloud.microsoft`, `*.office.com`, accounts/login hosts, Chrome update hosts.
3. **App control without decryption** (works even for pinned apps): CONNECT/SNI allow or deny per domain: block `desktop.chatgpt.com`, `android.chat.openai.com`, `ios.chat.openai.com`, `chat.deepseek.com` etc. as demo rules. Show it as a different decision type ("tunnel-block").
4. **ChatGPT Enterprise tie-in (cheap, strong demo):** on decrypted `https://chatgpt.com/*` add header `ChatGPT-Allowed-Workspace-Id` (config value) and block `/backend-anon/` (documented by OpenAI). Identity sibling owns who the user is.
5. **Block UDP/443** on the demo host (or document it) so Chromium apps fall back to TCP; mitmproxy regular mode has no HTTP/3.
6. **WebSocket policy:** mitmproxy decodes WS and permessage-deflate; run DLP on client text frames; redaction = rewrite the frame, block = close the connection (or inject server frames for Copilot). Zscaler's "drop WS if you cannot inspect" is a valid fail-closed switch: `ws_policy: inspect | drop`.
7. **Drift safety:** each precise adapter verifies its expected path (`parts`, `prompt`, `query_str`); when absent it logs `adapter_drift` and falls back to the generic adapter; fixtures carry a capture date.

**D1. Generic adapter (spec, applies to all apps)**
- Inputs: request bodies `application/json` (also `+json`, NDJSON), `x-www-form-urlencoded`, `multipart/form-data` (text parts; file parts go to the catalog/upload sibling), WS text frames; skip GET.
- Walk every string leaf. Parse strings that look like JSON (`[`/`{` first char) recursively to depth 3: needed for Gemini `f.req` (JSON inside JSON inside a form field) and Meta `variables`. Decode form values before parsing, re-encode after.
- Run DLP on the leaf text itself, never on raw JSON bytes (Netskope lesson: `\n` escapes break word boundaries). Skip leaves that are UUIDs, base64 > 256 chars or URLs on the same host; hash-dedupe repeated history.
- Redact in place: replace only the matching substring in that leaf, re-serialize with the same container; set `flow.request.content` (mitmproxy fixes `Content-Length`); form and nested JSON re-encoded exactly like the original.
- Block: for `fetch/XHR` (Sec-Fetch-Dest empty, or `Accept: application/json|event-stream`) return 403 JSON `{"error":{"message":"<block text>"}}`; for navigations return an HTML block page. Never forward a partial body.
- Known gap: blocked text is not shown inside the app UI (generic error toast at best).

**D4. Safe procedure to capture sanitized fixtures (own accounts only)**
1. Use a personal or throwaway test account (never a customer, employer or shared account); fresh browser profile; turn memory/history off where offered; no real data.
2. Prompts contain only canaries and fake secrets: `AICL-CANARY-001`, `AKIAIOSFODNN7EXAMPLE`, card `4111 1111 1111 1111`, a documented test PESEL, an `-----BEGIN PRIVATE KEY-----` stub. One prompt per capture: short, multi-line, with a code block, with a file, a follow-up turn.
3. Capture with our own mitmdump (`-w raw.flow` in a git-ignored dir) on `127.0.0.1:18081+`, not DevTools HAR "with sensitive data".
4. Run a sanitizer script (we write it, ~40 lines) before anything leaves the dir: drop `Cookie`, `Set-Cookie`, `Authorization`, `openai-sentinel-*`, `x-statsig-id`, `x-fb-*`, `at`, `lsd`, `fb_dtsg`, `__Secure-*`; replace org/user/chat UUIDs, emails and file names with stable placeholders; keep structure, key order and content types; keep SSE/WS framing byte-exact apart from placeholders.
5. Store as `tests/fixtures/webapps/<app>/<YYYY-MM-DD>/{request,response}.*` + `meta.yaml` (app, client build, date, prompt). Two-person diff review, gitleaks (MIT) in CI, delete the raw `.flow`, never paste fixtures into issues or chats.
6. Replay test: fixture -> adapter via the contract event; assert extraction, redacted shape and block response; a drift test removes the expected path and expects generic fallback.
7. Own account only, within the app's terms: no bulk automation, no scraping, no bypass of the Cloudflare challenge.
